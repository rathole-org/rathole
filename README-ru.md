Безопасный, стабильный и высокопроизводительный обратный прокси-сервер для обхода NAT, написанный на Rust

rathole, как [frp](https://github.com/fatedier/frp) и [ngrok](https://github.com/inconshreveable/ngrok), могут помочь предоставить доступ к сервису на устройстве, расположенном за NAT, через Интернет через сервер с общедоступным IP.

## Особенности

- **Высокая производительность** Может быть достигнута гораздо более высокая пропускная способность, чем у frp, и более стабильная работа с большим количеством подключений. Смотреть [Показатели](#Показатели)
- **Низкое потребление ресурсов** Потребляет гораздо меньше памяти, чем аналогичные инструменты. Смотреть [Показатели](#Показатели). [Двоичный файл](docs/build-guide.md) **такой же маленький, как ~500КБ** чтобы соответствовать ограничениям устройств, таких как встроенные устройства в качестве маршрутизаторов.
- **Безопасность** Токены служб являются обязательными и зависят от обслуживания. Сервер и клиенты сами отвечают за свои настройки. Благодаря дополнительному протоколу Noise можно легко настроить шифрование. Нет необходимости создавать самозаверяющий сертификат! Также поддерживается TLS.
- **Горячая перезагрузка** Службы могут быть добавлены или удалены динамически путем горячей перезагрузки файла конфигурации. HTTP API - это WIP.

## Быстрый старт

Полноценный `rathole` можно скачать на [релизной](https://github.com/rapiz1/rathole/releases) странице. Или [собрать из исходников](docs/build-guide.md) **для других платформ и сведение к минимуму двоичного кода**. [Docker образ](https://hub.docker.com/r/rapiz1/rathole) также имеется.

Использование `rathole` очень похоже на frp. Если у вас есть опыт работы с последним, то настройка будет для вас очень простой. Единственное отличие заключается в том, что настройка сервиса разделена на клиентскую и серверную части, и токен является обязательным.

Чтобы использовать "rathole", вам нужен сервер с общедоступным IP-адресом и устройство за NAT, где некоторые службы должны быть подключены к Интернету.

Предположим, у вас дома есть сетевой накопитель за NAT, и вы хотите подключить его ssh-сервис к Интернету:

1. На сервере, который имеет общедоступный IP-адрес

Создайте `server.toml` со следующим содержимым и адаптируйте его к вашим потребностям.

```toml
# server.toml
[server]
bind_addr = "0.0.0.0:2333" # `2333` указывает порт, который rathole прослушивает для клиентов

[server.services.my_nas_ssh]
token = "use_a_secret_that_only_you_know" # Токен, который используется для аутентификации клиента в сервисе. Измените на произвольное значение.
bind_addr = "0.0.0.0:5202" # `5202` указывает порт, который предоставляет доступ `my_nas_ssh` к Интернету
```

После запускай:

```bash
./rathole server.toml
```

2. На хосте, который находится за NAT (вашим сетевым накопителем)

Создай `client.toml` с приведенным ниже содержанием и приспособьте его к вашим потребностям.

```toml
# client.toml
[client]
remote_addr = "myserver.com:2333" # Адрес сервера. Порт должен совпадать с портом в `server.bind_addr`

[client.services.my_nas_ssh]
token = "use_a_secret_that_only_you_know" # Для прохождения проверки на сервере должно быть то же самое
local_addr = "127.0.0.1:22" # Адрес службы, которую необходимо переслать
```

После запускай:

```bash
./rathole client.toml
```

3. Теперь клиент попытается подключиться к серверу `myserver.com` через порт `2333`, и весь трафик, поступающий на `myserver.com:5202`, будет перенаправлен на порт клиента `22`.

Так что вы можете `ssh myserver.com:5202` подключиться по ssh к вашему NAS-накопителю.

Запуск `rathole` запустите как фоновую службу в Linux, проверьте [systemd примеры](./examples/systemd).

## Конфигурация

`rathole` может автоматически определять запуск в режиме сервера или клиента в соответствии с содержимым файла конфигурации, если только один из `[server]` и `[client]` блок присутствует, как в примере на [Быстрый старт](#Быстрый-старт).

Но `[client]` и `[server]` блок также можно поместить в один файл. Затем на стороне сервера запустите `rathole --server config.toml` и на стороне клиента запустите `rathole --client config.toml` чтобы явно указать `rathole` в рабочий режим.

Прежде чем перейти к полному описанию конфигурации, рекомендуется просмотреть [примеры конфигураций](./examples) чтобы получить представление о формате конфигурации.

Посмотрите [Транспорт](./docs/transport.md) для получения более подробной информации о шифровании и `транспортном` блоке.

Вот полная спецификация конфигураций:

```toml
[client]
remote_addr = "example.com:2333" # Необходимый. Адрес сервера
default_token = "default_token_if_not_specify" # Необязательный. Токен служб по умолчанию, если они не определяют свои собственные
heartbeat_timeout = 40 # Необязательный параметр. Установите значение 0, чтобы отключить проверку работоспособности на уровне приложения. Значение должно быть больше указанного. `server.heartbeat_interval`. По умолчанию: 40 секунд
retry_interval = 1 # Необязательный параметр. Интервал между повторными попытками подключения к серверу. По умолчанию: 1 секунда.

[client.transport] # Весь блок является необязательным. Укажите, какой транспорт использовать.
type = "tcp" # Необязательный параметр. Возможные значения: ["tcp", "tls", "noise"]. Значение по умолчанию: "tcp"

[client.transport.tcp] # Необязательный параметр. Также влияет на `noise` и `tls`.
proxy = "socks5://user:passwd@127.0.0.1:1080" # Необязательный параметр. Прокси-сервер, используемый для подключения к серверу. Поддерживаются протоколы `http` и `socks5`
nodelay = true # Необязательный параметр. Определяет, следует ли включить TCP_NODELAY, если это применимо, для уменьшения задержки, но уменьшения пропускной способности. По умолчанию: true
keepalive_secs = 20 # Необязательно. Укажите `tcp_keepalive_time` в `tcp(7)`, если применимо. По умолчанию: 20 секунд
keepalive_interval = 8 # Необязательно. Укажите `tcp_keepalive_intvl` в `tcp(7)`, если применимо. По умолчанию: 8 секунд

[client.transport.tls] # Необходимо, если `type` равен "tls"
trusted_root = "ca.pem" # Необходимо. Сертификат центра сертификации, подписавшего сертификат сервера.
hostname = "example.com" # Необязательный параметр. Имя хоста, которое клиент использует для проверки сертификата. Если не задано, используется значение `client.remote_addr` в качестве запасного варианта.

[client.transport.noise] # Протокол шумоподавления. Дополнительные пояснения см. в файле `docs/transport.md`.
pattern = "Noise_NK_25519_ChaChaPoly_BLAKE2s" # Необязательный параметр. Значение по умолчанию указано.
local_private_key = "key_encoded_in_base64" # Необязательный параметр
remote_public_key = "key_encoded_in_base64" # Необязательный параметр

[client.transport.websocket] # Необходимо, если `type` имеет значение "websocket".
tls = true # Если `true`, то будут использоваться настройки из `client.transport.tls`.

[client.services.service1] # Сервис, требующий переадресации. Имя `service1` может произвольно меняться, при условии, что оно совпадает с именем в конфигурации сервера.
type = "tcp" # Необязательный параметр. Протокол, который необходимо перенаправить. Возможные значения: ["tcp", "udp"]. Значение по умолчанию: "tcp"
token = "whatever" # Необходимо, если параметр `client.default_token` не задан.
local_addr = "127.0.0.1:1081" # Обязательно. Адрес службы, которую необходимо перенаправить.
nodelay = true # Необязательно. Переопределяйте значение `client.transport.nodelay` для каждой службы отдельно.
retry_interval = 1 # Необязательный параметр. Интервал между повторными попытками подключения к серверу. По умолчанию: наследует глобальную конфигурацию.

[client.services.service2] # Можно определить несколько сервисов.
local_addr = "127.0.0.1:1082"

[server]
bind_addr = "0.0.0.0:2333" # Necessary. Адрес, по которому сервер принимает клиентов. Как правило, достаточно изменить только порт.
default_token = "default_token_if_not_specify" # Необязательный параметр
heartbeat_interval = 30 # Необязательный параметр. Интервал между двумя сигналами подтверждения активности на уровне приложения. Установите значение 0, чтобы отключить отправку сигналов подтверждения активности. По умолчанию: 30 секунд
[server.transport] # То же самое, что и `[client.transport]`
type = "tcp"

[server.transport.tcp] # То же самое, что и у клиента
nodelay = true
keepalive_secs = 20
keepalive_interval = 8

[server.transport.tls] # Необходимо, если `type` равен "tls"
pkcs12 = "identify.pfx" # Необходимо. Файл .pkcs12 с сертификатом сервера и закрытым ключом.
pkcs12_password = "password" # Необходимо. Пароль файла PKCS12.

[server.transport.noise] # Тоже самое что и `[client.transport.noise]`
pattern = "Noise_NK_25519_ChaChaPoly_BLAKE2s"
local_private_key = "key_encoded_in_base64"
remote_public_key = "key_encoded_in_base64"

[server.transport.websocket] # Необходимо, если `type` имеет значение "websocket".
tls = true # Если `true`, то будут использоваться настройки из `server.transport.tls`.

[server.services.service1] # Название сервиса должно совпадать с названием на стороне клиента.
type = "tcp" # Необязательно. Аналогично настройкам клиента `[client.services.X.type]
token = "whatever" # Необходимо, если параметр `server.default_token` не задан.
bind_addr = "0.0.0.0:8081" # Необходимо. Адрес службы доступен по указанному адресу. Как правило, нужно изменить только порт.
nodelay = true # Необязательно. Аналогично настройкам клиента

[server.services.service2]
bind_addr = "0.0.0.1:8082"
```

### Регистрация

`rathole`, Как и во многих других программах на Rust, для управления уровнем логирования используются переменные окружения. Доступны следующие уровни: `info`, `warn`, `error`, `debug`, `trace`.

```shell
RUST_LOG=error ./rathole config.toml
```

запустите `rathole` с логированием только ошибок.

Если параметр `RUST_LOG` отсутствует, уровень логирования по умолчанию — `info`.

### Настройка

Начиная с версии 0.4.7, в rathole по умолчанию включена опция TCP_NODELAY, что должно положительно сказаться на задержке и интерактивных приложениях, таких как RDP и серверы Minecraft. Однако это немного снижает пропускную способность.

Если пропускная способность важнее, параметр TCP_NODELAY можно отключить, установив значение `nodelay = false`.

## Показатели

rathole имеет аналогичную задержку, как [frp](https://github.com/fatedier/frp), но может обрабатывать больше подключений, обеспечивать большую пропускную способность и потреблять меньше памяти.

Более подробная информация представлена ​​на отдельной странице. [Бенчмарк](./docs/benchmark.md).

**Однако не стоит воспринимать это как утверждение, что `rathole` волшебным образом сделает ваш переадресованный сервис в несколько раз быстрее, чем раньше.** Тестирование производительности проводится на локальном интерфейсе обратной связи, показывая результаты в условиях, когда задача ограничена производительностью процессора. Значительное улучшение может быть достигнуто, если сеть не является узким местом. К сожалению, для многих пользователей это не так. В этом случае основное преимущество заключается в снижении потребления ресурсов, в то время как пропускная способность и задержка могут существенно не улучшиться.
